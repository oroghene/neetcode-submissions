What a scrubbing-fleet control plane must do

The fleet sits inline with live attack traffic — every operation below has to be safe while packets are flowing through the hosts.

●Push mitigations

Get ACL / rate-limit / filter configs onto every host, globally, against a 30-second-class load SLA. A slow push is unmitigated attack traffic.

●Watch host health

largest_free_block_bytes is the early warning — total free memory looks fine while fragmentation makes the next mitigation unloadable.

●Reboot safely

Unhealthy ≠ safe to drain. Capacity gate per POP, one host per sweep, mutual exclusion between orchestrators — a host mid-mitigation is load-bearing.

●Rotate datapath keys

Scheduled rotation with a grace window: new key active, old key pending retirement until every host confirms reload.

register → mitigate → fragment → drain → reboot → resync

Build 1 — the stack I know

blackwatch-sim-aws: every moving part is code or infrastructure you operate. 6 runtime pieces, 3 languages, 1 IaC layer.

Go + gRPC + protobufControl plane: fleet registry, server-streaming config push, backlog replay for reconnecting hosts — ~300 lines that must themselves be operated.
Python host agentsLoad configs into a simulated dataplane, measure against the load SLA, report health including largest_free_block_bytes.
DynamoDB lease locksAuto-reboot mutual exclusion via conditional writes + fencing tokens — the subtlest code in the repo.
Lambda + EventBridgeDKGR key rotation; retirement grace window enforced by DynamoDB TTL.
CDK + CloudWatchThree tables, schedules, S3 archive; Prometheus /metrics scraped into a CloudWatch dashboard; EMF from Lambda.

Build 2 — the same system on Convex

blackwatch-sim-convex: the platform's primitives absorb the infrastructure. 1 runtime piece + agents, 1 language — verified against the self-hosted open-source backend.

schema.tsTables are the infra: hosts, mitigations, rebootLog, datapathKeys, loadEvents. No CDK layer, no codegen.
mitigations.activeOne reactive query is the push pipeline. Agents subscribe; placing a mitigation pushes the new set to every host. Reconnect resync = the same code path.
orchestrator.sweepThe entire drain decision — classify, capacity-gate, pick victim, audit log — is one serializable transaction. The distributed lock has no equivalent to get wrong.
crons + schedulerSweep every 15s; key rotation daily; retirement is a transactionally-scheduled function instead of a TTL.
components@convex-dev/rate-limiter guards the operator API — installed, not built.

What Convex does not replace

The honest half of the comparison — this replaces the control and ops plane, not the system.

●  The dataplaneLine-rate packet scrubbing is C/DPDK on metal. Nothing about a reactive backend touches kernel-bypass packet processing.
●  The on-host agentSomething still runs on each appliance to load filters and measure memory — here it speaks Convex instead of gRPC.
●  Appliance-fleet fan-outThousands of hosts each holding subscriptions is exactly Convex's model — but 10k+ inline appliances would need real load validation.
●  Partition semanticsThe gRPC design degrades explicitly on network partition; here you inherit the Convex client's reconnect behavior.

Each of these is a question worth asking, not a conclusion →

Questions this demo earns

For the Convex team — each one comes straight from something the build surfaced.

Fan-out ceiling

Would you trust a query subscription as the config push path for tens of thousands of appliance hosts? Where does the reactor's fan-out actually cap out today?

Metrics at scale

My metrics queries rerun on every heartbeat write. Is "move it to the aggregate component" the intended pattern, or is incremental view maintenance coming to core?

The lock I deleted

The sweep relies on OCC serializability instead of a distributed lock. At what write-contention level does retry pressure make that trade stop being free?

Determinism's edge

You built a deterministic runtime to get retries and subscriptions. What workload have you seen where that constraint genuinely didn't fit?
